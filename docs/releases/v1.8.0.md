# Wapbolt v1.8.0 — OpenAPI Import, Postman Export & Collection Runner ⚡

Rilis terbesar sejak v1.6 — Phase 1 dari roadmap Foundation & Adoption kini lengkap. Wapbolt kini bisa membaca koleksi dari ekosistem OpenAPI/Postman dan menjalankan seluruh collection secara otomatis dengan laporan hasil yang detail.

---

### ✨ Fitur Baru

#### 📥 Import OpenAPI 3.0 & Swagger 2.0
- **Auto-detect format**: Upload file JSON/YAML — Wapbolt otomatis mendeteksi apakah itu OpenAPI 3.0 atau Swagger 2.0.
- **Grouping by tags**: Endpoint dikelompokkan ke dalam folder berdasarkan tag OpenAPI.
- **Preview sebelum import**: Tampilkan jumlah endpoint yang akan diimport sebelum konfirmasi.
- **Parameter & body mapping**: Path params, query params, dan request body schema dikonversi ke format Wapbolt secara otomatis.
- Akses via: Import modal → tab **OpenAPI / Swagger**.

#### 📤 Export ke Postman Collection v2.1
- **Full fidelity export**: Folder hierarchy, auth config (Bearer/Basic/ApiKey), pre-request script, dan post-response script ikut terexport.
- **URL object lengkap**: Format `{raw, protocol, host, path, query}` sesuai spesifikasi Postman v2.1.
- File hasil export siap diimport langsung ke Postman tanpa modifikasi.

#### 🏃 Collection Runner — Versi Lengkap
- **Checklist per request**: Pilih request mana saja yang akan dijalankan.
- **Konfigurasi run**: Jumlah iterasi, delay antar request (ms), dan opsi stop on failure.
- **Progress bar live**: Pantau jalannya run secara real-time dengan counter request.
- **Laporan hasil detail**: Status code, response time, dan hasil test assertion per request.
- **Expand test assertions**: Klik result card untuk melihat detail pass/fail tiap `wap.test()`.
- **Export hasil**: Download laporan run sebagai JSON atau CSV.

---

### 🐛 Bug Fixes

#### Collection Runner — Stabilitas
- **Modal hilang saat run**: Panel runner kadang menutup sendiri di tengah run karena `CollectionItem` re-render. Diperbaiki dengan `createPortal` — panel kini dirender di luar DOM tree Sidebar.
- **Hasil tidak tampil**: Setelah run selesai, hasil disimpan di store. Panel yang dibuka kembali langsung menampilkan hasil run terakhir tanpa perlu run ulang.
- **UI stuck di "running"**: Jika terjadi error tak terduga, UI sebelumnya stuck di state running selamanya. Diperbaiki dengan `try/finally` yang memastikan state selalu transisi ke `finished`.
- **`wap.setEnv` error di post-request script**: Script yang menyimpan token hasil Login (`wap.setEnv('token', ...)`) gagal dengan `TypeError`. Post-request script runner kini punya API `wap` yang identik dengan pre-request: `setEnv`, `environment.set/get`, `collectionVariables.set/get`.

### 🔧 Peningkatan Teknis

- `lastRunResults` & `lastRunCollectionId` ditambahkan ke Zustand store untuk persistensi hasil run dalam satu sesi.
- `wap` object di pre-request dan post-request kini simetris — developer bisa pakai API yang sama di kedua lifecycle.
