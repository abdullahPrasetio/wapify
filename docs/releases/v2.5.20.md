# Wapbolt v2.5.20 / Wapbolt Local v1.0.0-beta.7 — Postman Migration Parity

**Tanggal:** 2026-08-03
**Type:** Minor release (New features + bug fixes)
**Berlaku untuk:** Wapbolt Desktop (Cloud) & Wapbolt Local (offline/SQLite)

---

## Highlights

- **Import Postman lebih lengkap** — Authorization (Bearer/Basic/API Key), Variables (collection-level), dan Pre-request/Test Scripts dari file export Postman kini benar-benar ter-import dan berfungsi, bukan cuma folder/request/header saja
- **Script sandbox `pm`/`wap` diperluas** — kompatibel dengan idiom umum script Postman: `require('moment'|'lodash'|'crypto-js')`, `CryptoJS` (Base64/Utf8), `response.code`, `pm.expect(...)` gaya chai (`.to.equal`, `.be.a`, `.include`, dst)
- **Variable overlay kini tahu collection variables** — field URL/Headers/Body/Auth (Username, Key, Value) menyorot `{{variable}}` hijau/kuning berdasarkan gabungan environment + collection variables, bukan environment saja
- **Masking + highlight sekaligus** — field Token (Bearer) & Password (Basic Auth) sekarang tetap ter-mask (bulatan) tapi variable `{{...}}` di dalamnya tetap ter-highlight dan bisa diklik untuk diedit
- **Auto Content-Type header (mirip Postman)** — kalau body dikirim tanpa header Content-Type eksplisit, Wapbolt otomatis menambahkan header yang sesuai (`application/json`, `application/xml`, dst) saat request dikirim, dan ditampilkan sebagai baris "hidden header" read-only di tab Headers — persis perilaku Postman
- **Duplicate Collection & Duplicate Folder** — menu klik-kanan baru di sidebar, menyalin seluruh isi (settings, auth, scripts, variables, sub-folder, request) secara rekursif ke salinan baru
- **Bugfix: race condition pada `pm.collectionVariables.set()`** — dua pemanggilan berturut-turut dalam satu script (mis. `set("access_token", ...)` lalu `set("refresh_token", ...)`) tidak lagi saling menimpa
- **Bugfix: header `disabled: true` dari Postman** — header yang di-uncheck di Postman sekarang benar-benar tidak ikut ter-import sebagai header aktif

## Changes

### Backend (Go) & Wapbolt Local (SQLite) — paralel di kedua sisi

- `ImportPostman`/`importPostman` — parse native `auth`, `variable`, `event` (prerequest/test) dari collection & request Postman; auth type yang belum didukung (mis. OAuth 2.0) di-fallback ke "No Auth" dan dihitung di `unsupported_auth_count` pada response
- `POST /api/v1/teams/:id/import` — route ini sekarang terdaftar di Wapbolt Local (sebelumnya 501, menyebabkan import selalu gagal)
- Header `disabled` field ditambahkan ke struct import, header yang disabled di-skip saat build request
- `POST /api/v1/folders/:id/duplicate` & `POST /api/v1/collections/:id/duplicate` — endpoint baru, menyalin folder/collection secara rekursif (sub-folder + request di dalamnya)

### Renderer (`packages/ui-shared`, dipakai Desktop & Local)

- `useDataStore.ts` — sandbox script `pm`/`wap` diperluas (`runPmScript`, `CryptoJSShim`, `wapboltScriptRequire`, `createScriptExpect`); helper `withDefaultContentType`/`getDefaultContentType` untuk auto Content-Type; `queueByKey` untuk serialize write ke collection/environment variables (fix race condition); action baru `duplicateCollection`/`duplicateFolder`
- `VariableOverlayInput.tsx` — prop `collectionId` (resolve variable dari collection + environment), prop `masked`/`revealed` (mask literal text tapi tetap highlight `{{var}}`)
- `KeyValueEditor.tsx` — prop `autoRows` untuk menampilkan baris read-only "auto-generated" (dipakai untuk auto Content-Type di tab Headers)
- `MainArea.tsx` / `CollectionTabContent.tsx` — Bearer Token & Basic Auth Password pakai `VariableOverlayInput` bermode masked; auto Content-Type row di tab Headers
- `Sidebar.tsx` — menu "Duplicate Collection" & "Duplicate Folder" di context menu

## Bug Fixes

- **[Import]** `POST /api/v1/teams/:id/import` tidak terdaftar di Wapbolt Local → import Postman JSON selalu gagal
- **[Import]** Header `disabled: true` di Postman ikut ter-import sebagai header aktif
- **[Script Sandbox]** `responseBody` tidak reachable sebagai identifier bare di script — sekarang di-bind sebagai parameter fungsi
- **[Script Sandbox]** `const moment = require('moment')` gagal dengan `SyntaxError` karena `moment`/`_` sempat di-bind sebagai parameter `AsyncFunction` — dihapus dari bound-parameter, hanya reachable via `require()`
- **[Variables]** `pm.collectionVariables.set()` dua kali berturut-turut dalam satu script kehilangan salah satu nilai akibat race condition read-merge-write yang tidak di-serialize
- **[Auth]** Field Token/Username/Key/Value di Authorization tidak resolve `{{variable}}` dari collection scope, dianggap plain text

## Migrasi Database

- **Postgres**: migrasi `000033_add_settings_to_collections` (kolom `auth_config`, `pre_request_script`, `post_request_script`, `variables` di tabel `collections`) — sudah dijalankan di dev, **masih pending di staging & production**, jalankan `make migrate-up` sebelum deploy binary ini
- **SQLite (Wapbolt Local)**: migrasi `004_collection_settings.sql` (kolom yang sama) — otomatis berjalan saat app dibuka, tidak perlu tindakan manual
